# Deployment Guide

This guide covers containerisation and deployment of PersuasUI to Azure Container Apps.

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Azure Container Apps Environment                  │
│                                                                      │
│   ┌──────────┐       ┌──────────────────┐       ┌──────────────┐   │
│   │  client  │──────▶│  session_manager │──────▶│   persuasio  │   │
│   │ (public) │       │    (internal)    │       │  (internal)  │   │
│   └──────────┘       └──────────────────┘       └──────────────┘   │
│                                                         │           │
└─────────────────────────────────────────────────────────┼───────────┘
                                                          │
                                              ┌───────────┴───────────┐
                                              │                       │
                                         ┌────▼────┐            ┌─────▼─────┐
                                         │ Neo4j   │            │ PostgreSQL│
                                         │   DB    │            │    DBs    │
                                         └─────────┘            └───────────┘
```

- **client**: Gradio web UI (public ingress)
- **session_manager**: FastAPI business logic (internal only)
- **persuasio**: FastAPI LLM dialogue backend (internal only)
- **Databases**: Neo4j for knowledge graph, PostgreSQL for sessions/logs

## Prerequisites

- [Azure CLI](https://docs.microsoft.com/en-us/cli/azure/install-azure-cli)
- [Docker](https://docs.docker.com/get-docker/)
- An Azure subscription
- Azure Container Registry (ACR) or other container registry

## Database Requirements

The platform requires the following databases:

| Database | Service | Purpose |
|----------|---------|---------|
| PostgreSQL (session_manager) | session_manager | Sessions, participants, dialogue history |
| PostgreSQL (persuasio main) | persuasio | Main persuasio data |
| PostgreSQL (persuasio logs) | persuasio | Logging/telemetry |
| Neo4j | persuasio | Knowledge graph for RAG |

For Azure, you can use:
- **Azure Database for PostgreSQL - Flexible Server** for PostgreSQL
- **Neo4j AuraDB** or a self-hosted Neo4j container for the graph database

Create the databases before deploying the containers, and have the connection details ready for environment variables.

## 1. Dockerfiles

Each service has a Dockerfile using `uvicorn` for production.

### System Dependencies for PostgreSQL

Services that connect to PostgreSQL require system packages to build `psycopg2`:

- `gcc` - C compiler for building native extensions
- `libpq-dev` - PostgreSQL client library headers

These are installed in the Dockerfile before `uv sync`.

> **Note**: An alternative is to use `psycopg2-binary` (pre-compiled wheels) which doesn't require system deps, but the psycopg maintainers recommend against it for production. Another option is `psycopg[binary]` (psycopg3) which provides pre-built binaries and async support.

### persuasio/Dockerfile

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install system dependencies for psycopg2 (PostgreSQL driver)
RUN apt-get update && apt-get install -y \
    gcc \
    libpq-dev \
    && rm -rf /var/lib/apt/lists/*

# Install uv
RUN pip install uv

# Copy dependency files
COPY pyproject.toml uv.lock ./

# Install dependencies
RUN uv sync --frozen --no-dev

# Copy application code
COPY persuasio/ ./persuasio/

EXPOSE 8080

# Run with uvicorn
CMD [".venv/bin/uvicorn", "persuasio.app:app", "--host", "0.0.0.0", "--port", "8080", "--workers", "4"]
```

### persuasui/client/Dockerfile

The client doesn't need PostgreSQL system dependencies - it communicates with session_manager via HTTP.

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install uv (no system deps needed - client uses HTTP only)
RUN pip install uv

# Copy dependency files
COPY pyproject.toml uv.lock ./

# Install dependencies
RUN uv sync --frozen --no-dev

# Copy application code
COPY client/ ./client/

EXPOSE 7860

# Run Gradio app
CMD [".venv/bin/python", "-m", "client.app"]
```

## 2. Build and Push Images

### Login to Azure

```bash
az login
az acr login --name <your-registry-name>
```

### Build and Push

```bash
REGISTRY=<your-registry-name>.azurecr.io

# Build and push persuasio (from Code/persuasio/)
cd Code/persuasio
docker build -t $REGISTRY/persuasio:latest .
docker push $REGISTRY/persuasio:latest

# Build and push session_manager (from Code/persuasui/session_manager/)
cd Code/persuasui/session_manager
docker build -t $REGISTRY/session-manager:latest .
docker push $REGISTRY/session-manager:latest

# Build and push client (from Code/persuasui/client/)
cd Code/persuasui/client
docker build -t $REGISTRY/client:latest .
docker push $REGISTRY/client:latest
```

## 3. Azure Container Apps Setup

### Create Resource Group and Environment

```bash
RESOURCE_GROUP=persuasui-rg
LOCATION=uksouth
ENVIRONMENT=persuasui-env

# Create resource group
az group create --name $RESOURCE_GROUP --location $LOCATION

# Create Container Apps environment
az containerapp env create \
    --name $ENVIRONMENT \
    --resource-group $RESOURCE_GROUP \
    --location $LOCATION
```

### Deploy Services

Deploy in dependency order: persuasio → session_manager → client.

#### Deploy persuasio (internal)

```bash
az containerapp create \
    --name persuasio \
    --resource-group $RESOURCE_GROUP \
    --environment $ENVIRONMENT \
    --image $REGISTRY/persuasio:latest \
    --target-port 8080 \
    --ingress internal \
    --min-replicas 1 \
    --max-replicas 3 \
    --env-vars \
        PERSUASIO_MODE=prod \
        PERSUASIO_API_KEY=<your-api-key> \
        NEO4J_URL=<neo4j-connection-string> \
        NEO4J_USERNAME=<neo4j-user> \
        NEO4J_PASSWORD=<neo4j-password> \
        PSQL_HOST=<postgres-host> \
        PSQL_PORT=5432 \
        PSQL_DB_NAME=<db-name> \
        PSQL_USERNAME=<postgres-user> \
        PSQL_PASSWORD=<postgres-password> \
        PSQL_SSLMODE=require \
        LOGS_PSQL_HOST=<logs-postgres-host> \
        LOGS_PSQL_PORT=5432 \
        LOGS_PSQL_DB_NAME=<logs-db-name> \
        LOGS_PSQL_USERNAME=<logs-postgres-user> \
        LOGS_PSQL_PASSWORD=<logs-postgres-password> \
        LOGS_PSQL_SSLMODE=require
```

#### Deploy session_manager (internal)

```bash
# Get persuasio's internal URL
PERSUASIO_URL=$(az containerapp show \
    --name persuasio \
    --resource-group $RESOURCE_GROUP \
    --query properties.configuration.ingress.fqdn -o tsv)

az containerapp create \
    --name session-manager \
    --resource-group $RESOURCE_GROUP \
    --environment $ENVIRONMENT \
    --image $REGISTRY/session-manager:latest \
    --target-port 8000 \
    --ingress internal \
    --min-replicas 1 \
    --max-replicas 3 \
    --env-vars \
        SESSION_MANAGER_MODE=prod \
        SESSION_MANAGER_API_KEY=<your-api-key> \
        PERSUASIO_API_KEY=<persuasio-api-key> \
        PERSUASIO_BASE_URL=https://$PERSUASIO_URL \
        PSQL_HOST=<postgres-host> \
        PSQL_PORT=5432 \
        PSQL_DB_NAME=<db-name> \
        PSQL_USERNAME=<postgres-user> \
        PSQL_PASSWORD=<postgres-password> \
        PSQL_SSLMODE=require
```

#### Deploy client (public)

```bash
# Get session_manager's internal URL
SESSION_MANAGER_URL=$(az containerapp show \
    --name session-manager \
    --resource-group $RESOURCE_GROUP \
    --query properties.configuration.ingress.fqdn -o tsv)

az containerapp create \
    --name client \
    --resource-group $RESOURCE_GROUP \
    --environment $ENVIRONMENT \
    --image $REGISTRY/client:latest \
    --target-port 7860 \
    --ingress external \
    --min-replicas 1 \
    --max-replicas 3 \
    --env-vars \
        CLIENT_MODE=prod \
        SESSION_MANAGER_API_KEY=<session-manager-api-key> \
        SESSION_MANAGER_BASE_URL=https://$SESSION_MANAGER_URL
```

## 5. Updating Deployments

To update a service after pushing a new image:

```bash
az containerapp update \
    --name <service-name> \
    --resource-group $RESOURCE_GROUP \
    --image $REGISTRY/<service-name>:latest
```

## 6. Monitoring and Logs

View logs for a service:

```bash
az containerapp logs show \
    --name <service-name> \
    --resource-group $RESOURCE_GROUP \
    --follow
```

## 7. Cleanup

To delete all resources:

```bash
az group delete --name $RESOURCE_GROUP --yes --no-wait
```
